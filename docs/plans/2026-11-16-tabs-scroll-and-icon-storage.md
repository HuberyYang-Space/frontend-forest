# 标签切换原位修复与图标存储清理计划

> **执行要求：** 用户确认本计划及下列待决范围后，使用 `superpowers:executing-plans` 按任务实施；代码修复遵循 TDD，交付前执行 `superpowers:verification-before-completion`。本文件记录已确认方案、实施证据及尚未执行的发布与删除步骤。

**状态：** 2026-11-16 用户确认三项方案并选择原地实施。前后端本地实现与验收已通过，用户已授权同轮提交发布；26 个旧云图标已备份，实际删除前仍须用户再次确认。

**目标：** 点击分类标签时保持页面纵向位置和 banner 布局；资源条目和搜索引擎图标使用本地资产，清理经确认的七牛图标专用集成。

**技术方案：** 沿用 Vue、Element Plus 标签页、分类动态加载和 ElImage。为标签页持久内容区设置至少一个视口的最小高度，覆盖分类切换的瞬时空内容、加载、成功与失败状态。搜索引擎图标保存为本地 WebP。关联后端与云对象单列清理边界。

## 调研一：标签切换跳动

### 现有链路

[ResourceCatalog.vue](../../src/components/ResourceCatalog.vue) 通过 `activeId` 和 Element Plus 切换分类；[useResourceCategory.ts](../../src/composables/useResourceCategory.ts) 在同步 watch 中清空资源并进入 loading，随后等待动态导入。旧分类内容由 `v-if` 移除，新分类通过标签页内部状态和异步加载出现；骨架屏有 200ms throttle。在过渡期间，持久内容区没有最小高度。

[useParallax.ts](../../src/composables/useParallax.ts) 根据 `window.scrollY` 更新 banner 的图层和按钮位置。因此目录引起页面滚动后，banner 视差也变化；此次测量未发现 banner 外框高度改变，尚无证据支持另改视差算法。

### 观测校准与复现

- 已知结果探针：算式结果为 5；页面标题为“前端森林”；banner 外框为一个视口高。
- 自动化定位器点击会先将目标滚入视口中央，混入工具引起的滚动。这类采样已剔除。有效采样使用原生坐标点击，并等待滚动和布局稳定。
- 原生点击当前已选标签的控制组：滚动差 **0px**，证明点击手段本身不改变纵向位置。
- 未修改的本地原页面，1920×963 视口，“框架 46 → 组件库 46”：`scrollY` 从 **743 → 265**，差 **-478px**；前后文档高度均为 **2730px**，banner 外框均为 **963px**。同数量分类也复现，排除了“仅最终列表更短”的解释。
- 原始复现循环对 `abs(after.scrollY - before.scrollY) <= 1` 判红，返回 `[FF-tabs] 原始页面原生点击复现纵向跳动 -478px`。

### 隔离单变量对照

临时诊断代理转发现有本地页面，仅注入诊断 CSS；没有改正式源码。每个变体均从新文档加载，通过 meta 标记和真实目标元素的 computed style 确认设置实际生效，再使用原生点击。下表均为同一 1920×907 视口、标签顶边 300px、“框架 46 → 组件库 46”。

| 变体                         | 切换前 scrollY | 切换后 scrollY | 差值   |
| ---------------------------- | -------------- | -------------- | ------ |
| 原始页面行为                 | 687            | 265            | -422px |
| 仅关闭根节点滚动锚定         | 687            | 265            | -422px |
| 仅内容区 `min-height: 100vh` | 687            | 687            | 0px    |
| 最小高度并关闭内容区滚动锚定 | 687            | 687            | 0px    |

最小高度变体还验证了标签顶边 80px、“框架 46 → 运行时 5”：`scrollY` **907 → 907**，内容区最小高度 **907px**，banner 外框高度和森林图层位置不变。

**结论：** 过渡时内容区高度丢失会压缩可滚动范围，浏览器调整滚动位置。只关闭滚动锚定无效；持久内容区保留一屏空间即可通过已复现场景。以上是桌面 Chrome 调研证据，尚不代表完整修复或全部设备验收。

本地页面在本轮调研时处于“重试加载歌单”状态；临时代理的媒体 API 请求也有 502。本轮仅使用其分类目录和布局进行对照，不把这些页面结果作为播放器或媒体生产链路的新验收。

官方参考：[Element Plus Tabs](https://element-plus.org/en-US/component/tabs)、[MDN 滚动锚定](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll_anchoring/Overview)。是否采用滚动锚定相关处理，以上述本项目原生点击对照为准。

### 方案比较与建议

| 方案                           | 影响                                                                       | 决定         |
| ------------------------------ | -------------------------------------------------------------------------- | ------------ |
| 持久内容区保留至少一屏高度     | 加载、失败和短分类都具备足够页面空间；短分类下方会留白，长分类继续自然增长 | **建议采用** |
| 切换后调用 `scrollTo` 恢复位置 | 中间仍可能闪跳；新文档太短时恢复受限，还会再次驱动 banner 视差             | 不采用       |
| 缓存全部面板或保留历史最大高度 | 改变仅挂载当前分类的约定，或形成随访问历史增长的空白                       | 不采用       |

不修改组件库，不全局禁用滚动锚定，不重做 banner。真实回归若发现独立 banner 缺陷，先提供复现证据并重新确认范围。
