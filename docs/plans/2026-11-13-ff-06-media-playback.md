## 诊断证据

### 真实页面与最小复现

- 正式站点点击播放后，进度停在 `00:00`，出现 `An audio error has occurred, player will skip forward in 2 seconds.`，随后自动跳曲。重新加载后重复复现；console 也捕获到 `NotSupportedError: Failed to load because no supported source was found.`。
- 用项目实际 `fetchPlaylist(signal)` 读取三个正式同源接口，共 37 首：周杰伦 11 首、林俊杰 12 首、G.E.M.邓紫棋 14 首。歌单请求成功和播放器已创建不能证明媒体能播放。
- 原生 `<audio>` 对远程文件同样失败：可信点击、`MediaError.code=4`、`networkState=3`、`currentTime=0`。该最小复现不依赖 APlayer。
- 先用已知时长 3 秒的 WAV 校准浏览器，再播放同一 Mojito FLAC 的前 1 MiB 片段。两者 `play()` 均 fulfilled、`readyState=4`、无媒体错误，媒体时间分别推进到 1.344 秒和 1.26 秒。这里只证明当前 Chrome 能解码该片段，未声称全曲、其他浏览器或扬声器听感已验收。
- 初期探针用固定墙钟等待后要求媒体时间达到指定值，校准未通过；已改成按媒体事件及媒体时间推进判定，重新跑校准和失败对照。没有将探针超时或阈值失配归因于产品。
- 直接导航到 FLAC 文件被浏览器诊断通道以 `ERR_BLOCKED_BY_CLIENT` 拒绝；这一限制没有用作产品根因证据，后续对照均在同一官方浏览器通道的页面内执行。

### HTTP 与缓存对照

请求实际媒体 URL，保持路径和 Range 不变，仅对照 Referer；全量审计为每个资源使用独立查询参数，并逐项确认首次响应的 `x-qnm-cache: Miss`。

| 资源 | 数量 | 正式站点 Referer，冷缓存       | 无 Referer 对照                        |
| ---- | ---: | ------------------------------ | -------------------------------------- |
| 音频 |   37 | 37 项均为 403 application/json | 37 项均为 206 audio/flac               |
| 歌词 |   37 | 37 项均为 403 application/json | 37 项均为 206 application/octet-stream |
| 封面 |    3 | 3 项均为 403 application/json  | 3 项均为 206 image/jpeg                |

77 个失败响应正文都严格等于 `{"error":"referer forbidden"}`。对照响应分别核对 `fLaC` 文件头、LRC 文本前缀和 JPEG 文件头；没有把后缀正确或 HTTP 2xx 当作媒体内容正确。审计命令以退出码 1 报告正式来源不可用，未将它记作通过。

对同一 Mojito URL 的独立缓存键，顺序对照得到：

1. 携带 `Referer: https://forest.huberyyang.site/`：403，`x-qnm-cache: Miss`，回源日志也含 403。
2. 不携带 Referer：206 audio/flac，`x-qnm-cache: Miss,MissFg`。
3. 再携带正式站点 Referer：206 audio/flac，`x-qnm-cache: Hit`。

因此 CDN 命中可能掩盖回源拒绝，导致部分曲目偶尔能播。上述命中仅代表该次请求的节点与缓存键；浏览器原页面仍复现失败，不能用 curl 命中成功宣称浏览器已修复。无 Referer 请求只用于诊断对照，不作为修复后的验收条件。

### 根因与诊断阶段的配置边界

**已确认：媒体源的存储空间 Referer 防盗链拒绝正式站点来源；CDN 缓存会掩盖这一拒绝。** 错误 JSON 被当作媒体响应后表现为浏览器媒体加载失败或 ORB 拦截。响应已有 `Access-Control-Allow-Origin: *`，再加相同的 CORS 响应头不能让 403 变成音频。

七牛[存储 FAQ 的 Q9](https://developer-doc.qiniu.com/faq/kodo/basic-use-of/12957-kodo-nomarl-faq)将 `referer forbidden` 定位到存储空间设置，明确区分于 CDN 的防盗链。诊断阶段的证据与该说明一致，但当时尚未读取控制台中的空间名称、黑白名单模式及完整规则，不能把“白名单漏项”当成已经看到的配置事实；后续核对及修复见[实施记录](#实施记录)。
